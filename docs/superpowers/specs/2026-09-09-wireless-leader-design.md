# SO-ARM101 主臂无线化设计

## 目标

将 SO-ARM101 主臂从电脑 USB 串口输入改为 XIAO ESP32-C3 WiFi 输入，同时保留电脑作为控制中继、校准执行者、安全监督者和日志记录者。主臂无线化后，正常遥操不再需要主臂到电脑的 USB 数据线；现有 USB 主臂模式继续作为显式备用模式。

成功后的控制链路为：

```text
主臂 STS3215 舵机
  -> 主臂 XIAO ESP32-C3（50 Hz 原始位置采样，扭矩关闭）
  -> WiFi / micro-ROS
  -> 电脑（主臂校准、安全检查、相对映射、会话与日志）
  -> /joint_command（30 Hz）
  -> 现有从臂 XIAO ESP32-C3
  -> 从臂 STS3215 舵机
```

目标端到端控制链确认延迟的 p95 小于 100 ms。主臂链路中断时从臂保持；链路恢复后约 1 秒平滑追到主臂当前姿态。手机热点改变电脑 IP 后，两个 XIAO 应自动重新发现电脑 agent，不需要重新烧录。

## 已确认的设计决策

- 使用第二块 Seeed XIAO ESP32-C3 和独立的主臂固件工程。
- 主臂 XIAO 与六个主臂舵机共用稳定 5 V 电源和公共地。
- 主臂舵机需要供电以回读位置，但遥操期间扭矩必须关闭。
- 电脑保留为主从臂之间的无线中继。
- 主臂 XIAO 发布原始舵机位置；电脑继续读取 `cali/my_leader.json` 完成校准和归一化。
- 主臂采样和发布频率为 50 Hz，电脑向从臂发布命令的频率保持 30 Hz。
- 主臂断线时停止向从臂发送新目标；恢复后使用新会话并在约 1 秒内平滑追赶。
- 正常启动默认使用无线主臂；有线主臂通过显式参数保留，不做自动模式猜测。
- 继续使用手机热点，但取消固件中的固定 agent IP，改为局域网自动发现。

## 范围与非目标

本项目包含主臂固件、共享 agent 发现模块、电脑端无线主臂输入、启动脚本、指标日志、自动测试和分阶段实机验证。

首版明确不包含：

- 主从 XIAO 直接通信；
- 脱离电脑独立遥操；
- 主臂力反馈；
- 在 XIAO 上执行或保存主臂校准；
- 运行时自动选择主臂角色；
- 自动猜测有线或无线主臂；
- 100 Hz 主臂采样；
- 修改从臂的 12.0 rad/s 速度配置、舵机速度、加速度或校准值。

WiFi 凭据仍由被忽略的本地配置文件提供，不进入源码、日志、测试证据或 Git 提交。

## 硬件与电气边界

主臂 XIAO 使用与现有从臂 XIAO 相同的 STS3215 串行总线连接方式：1 Mbps，XIAO `D7` 接收、`D6` 发送。XIAO 和舵机由同一稳定 5 V 电源供电并共地。设计假定当前驱动板已经完成适当的单总线电气转换；固件设计不改变总线电平和方向控制电路。

首次烧录和 USB 调试时必须断开舵机 5 V。只有在驱动板明确具备电源隔离或 OR-ing、确认不会在 USB 5 V 与外部 5 V 之间回灌后，才允许同时连接 USB 和舵机电源；否则调试时二者只能选择一个供电来源。

主臂固件只允许以下舵机操作：

1. Ping 和读取型号、固件、Homing Offset、位置限位、扭矩状态、位置、电压和温度；
2. 将 `Torque_Enable` 写为关闭；
3. 回读 `Torque_Enable`，确认关闭成功。

主臂固件禁止写入 Goal Position、Goal Speed、Acceleration、Homing Offset、位置限位或其他校准寄存器。即使收到异常 ROS 数据，主臂固件也不存在位置命令订阅者。

## Agent 自动发现

电脑新增一个轻量 UDP 发现广播器。它在当前 WiFi 接口上每秒广播一次发现报文，固定使用发现端口 `8889`。报文包含：

- 固定魔数 `SOARM_AGENT`；
- 发现协议版本 `1`；
- 本次电脑进程随机生成的 32 位 nonce；
- micro-ROS agent UDP 端口，默认 `8888`。

XIAO 使用报文来源地址作为 agent IP，而不是相信报文中自报的 IP。XIAO 只接受魔数、版本和端口范围合法的报文。发现报文不包含 SSID、WiFi 密码或其他凭据。

考虑到部分手机热点会过滤客户端广播，发现流程分两级：先发送/监听局域网广播；连续 3 秒未发现时，XIAO 根据 DHCP 子网掩码，对当前 `/24` 子网的发现端口执行有速率限制的单播探测，电脑发现服务以单播回应。单播扫描只探测固定发现端口，不尝试登录或扫描其他服务；找到有效 nonce 后立即停止。若热点不是 `/24`，不进行无界扫描，而是继续广播并在串口状态中报告 `DISCOVERY_UNSUPPORTED_SUBNET`。

XIAO 启动后先连接已配置的 WiFi，再等待发现报文，然后设置 micro-ROS WiFi transport。两个 XIAO 使用不同节点名，并从各自芯片身份生成不同 XRCE client key。若 agent 长时间失联，XIAO 释放当前会话并重新进入发现流程；若 micro-ROS 栈无法可靠释放，允许通过受控重启恢复，重启后重新发现，不保存固定 IP。

`start_soarm_demo.sh` 仍可校验预期热点名称，但不再要求电脑 IP 等于编译时常量。脚本负责启动 micro-ROS agent 和发现广播器，并在退出时只清理本次由它启动的进程。

此发现协议解决地址变化，不提供不可信局域网中的密码学认证。首版安全边界是用户控制的个人热点。会话 ID、序列号、设备状态和校准 CRC 用于防止误接和旧数据复用，但不替代网络加密。

## 主臂固件

新建独立工程 `firmware/xiao_soarm_leader/`。主臂和从臂固件共享纯逻辑的发现报文解析与协议常量，但保持独立入口、状态机和舵机写权限。

### 启动顺序

1. 初始化 USB 串口日志和 STS3215 总线。
2. 扫描 ID 1 到 6，确认六个型号均为 `777`。
3. 对六个舵机关闭扭矩并逐个回读确认。
4. 读取当前 EEPROM 校准字段并计算校准 CRC32。
5. 连接 WiFi并自动发现电脑 agent。
6. 创建主臂 ROS 节点、原始状态 publisher 和健康状态 publisher。
7. 连续有效读取后进入 `READY`，开始发布有效主臂样本。

### 状态机

主臂状态定义为：

| 值 | 状态 | 含义 |
|---:|---|---|
| 0 | `STARTING` | 正在初始化总线、校验舵机并关闭扭矩 |
| 1 | `WAITING_AGENT` | 舵机安全条件满足，等待电脑 agent |
| 2 | `READY` | 六舵机在线、扭矩关闭、位置读取有效 |
| 3 | `BUS_FAULT` | 舵机缺失、型号错误、扭矩关闭失败或持续读取失败 |

任意一个舵机缺失、型号不是 `777` 或扭矩关闭无法确认时，固件不得进入 `READY`。单次读取失败时不发布不完整动作样本并累计错误；连续三次读取失败进入 `BUS_FAULT`。恢复需要重新扫描、重新关闭并确认扭矩，随后连续十次完整读取有效，才能回到 `READY`。状态 publisher 在非就绪状态仍继续发布诊断信息。

### 校准 CRC

CRC32 输入按 ID 1 到 6 的固定顺序排列，每个舵机依次包含：ID、型号、Homing Offset、Min Position Limit、Max Position Limit。整数按明确的小端字节序编码，使用标准 CRC-32/ISO-HDLC 参数。电脑从 `cali/my_leader.json` 和预期型号生成相同字节序列并计算 CRC。

CRC 只用于确认当前主臂 EEPROM 与电脑校准文件属于同一套机械臂。XIAO 不使用这些校准字段生成归一化动作，也不修改它们。

### 发布频率

- 舵机位置读取和原始动作发布：50 Hz；
- 主臂健康状态发布：10 Hz；
- 串口摘要日志：低频输出，避免阻塞控制循环。

## ROS 消息协议

为了保持微控制器消息依赖简单，首版使用 `std_msgs/msg/Int32MultiArray`，并在电脑端严格检查固定长度、版本和字段范围。raw state 与 status 均使用 best-effort、keep-last、depth 1 QoS，防止旧样本排队造成控制滞后。

### `/leader/raw_state`

固定 11 个整数：

| 下标 | 字段 |
|---:|---|
| 0 | 协议版本，固定为 `1` |
| 1 | 32 位启动会话 ID |
| 2 | 32 位采样序列号 |
| 3 | XIAO 启动后的毫秒数 |
| 4 | 舵机位置响应掩码，正常为 `0x3f` |
| 5–10 | ID 1–6 的原始 Present Position |

原始位置使用有符号 32 位整数，因为应用 Homing Offset 后的位置可能小于 0 或大于 4095。固件只在本次六舵机读取全部有效时发布该消息。

### `/leader/status`

固定 13 个整数：

| 下标 | 字段 |
|---:|---|
| 0 | 协议版本 |
| 1 | 主臂状态 |
| 2 | 32 位启动会话 ID |
| 3 | 最后发布的采样序列号 |
| 4 | 舵机响应掩码 |
| 5 | 型号匹配掩码 |
| 6 | 扭矩关闭确认掩码 |
| 7 | 校准 CRC32 |
| 8 | 总读取周期数 |
| 9 | 读取错误数 |
| 10 | 扭矩关闭或确认错误数 |
| 11 | XIAO 启动后的毫秒数 |
| 12 | WiFi RSSI，单位 dBm |

所有 32 位无符号字段通过 `Int32MultiArray` 传输时按位保留，电脑解析后转换为无符号值。电脑只接受 `READY`、三个掩码均为 `0x3f`、CRC 匹配且会话/序列合法的动作。

## 电脑端主臂输入

电脑端建立统一的主臂输入接口，使后续控制逻辑不关心动作来自 USB 还是 WiFi：

- `WiredLeaderSource` 包装现有 `SO101Leader`，保持当前行为；
- `WirelessLeaderSource` 订阅 `/leader/raw_state` 和 `/leader/status`，执行协议、健康状态、校准和时效检查。

无线输入使用 `cali/my_leader.json` 中现有的 `range_min`、`range_max` 和 `drive_mode`，按 LeRobot 当前 `MotorNormMode` 规则归一化：主体五关节为 `RANGE_M100_100`，夹爪为 `RANGE_0_100`。实现必须用单元测试证明相同原始输入与现有 `FeetechMotorsBus` 产生相同动作值。

主臂动作只有在以下条件全部满足时才变为可用：

- `/leader/status` 为 `READY`；
- 响应、型号和扭矩关闭掩码均为 `0x3f`；
- EEPROM 校准 CRC 与 `my_leader.json` 一致；
- raw state 与 status 的启动会话 ID 一致；
- 序列号比上次接受值更新；
- 最近有效主臂样本年龄不超过 150 ms；
- 六个原始位置和归一化结果均在可接受范围内。

任何条件失效时，电脑立即停止从主臂生成新目标，不重复使用最后一帧伪装成新动作。

## 启动脚本和模式选择

`start_soarm_demo.sh` 增加显式参数：

```bash
./start_soarm_demo.sh                         # 默认 --leader wireless
./start_soarm_demo.sh --leader wireless
./start_soarm_demo.sh --leader wired
./start_soarm_demo.sh --leader wireless --check
./start_soarm_demo.sh --leader wired --check
```

无线模式不检查主臂 USB 串口，而是等待主臂 raw state 和 status，并在启动运动前打印六舵机、扭矩、CRC、RSSI 和采样频率预检结果。有线模式保留当前稳定 `/dev/serial/by-id/` 路径、校准检查和串口锁。

`--check` 永远不启动遥操。无线 check 同时检查主臂 XIAO、从臂 XIAO、agent、发现服务和两个状态主题；有线 check 保持主臂串口检查并检查无线从臂。

脚本不会自动在两种主臂之间切换，避免两种输入同时存在时选错设备。

开发期间保持现有有线默认行为，避免未完成的无线主臂影响当前演示。只有主臂无线实机闸门全部通过并保存证据后，最终提交才把无参数启动切换为无线默认。

## 数据超时与恢复

主臂 50 Hz 发布时，电脑将 150 ms 无有效样本视为主臂链路中断。中断后立即停止发布 `/joint_command`；现有从臂固件在 500 ms 看门狗到期后进入 `HOLDING_TIMEOUT` 并保持最后目标。

电脑保留启动时建立的主从相对映射关系。主臂恢复、重启或切换到新启动会话后：

1. 等待 `READY` 和连续的新序列样本；
2. 读取从臂当前实测姿态；
3. 根据保留的相对映射和主臂当前姿态计算应到达目标；
4. 创建新的从臂控制会话；
5. 从从臂保持姿态开始，在约 1 秒内平滑追到当前目标；
6. 追赶期间继续使用每命令 `0.24 rad` 边界和从臂固件现有安全检查。

若主臂在恢复追赶过程中再次失联，立即取消追赶并再次保持。若主臂和从臂同时恢复，必须先确认两端状态与实测姿态，再开始追赶；任何一端不健康都不得发送动作。

现有从臂自身 WiFi 恢复策略和 3 秒恢复混合保持不变。本设计中的约 1 秒只用于主臂输入链路恢复。

## 可观测性

现有遥操 CSV 增加以下主臂字段：

- `leader_boot_session_id`；
- `leader_sample_sequence`；
- `leader_sample_gap_ms`；
- `leader_sample_age_ms`；
- `leader_response_mask`；
- `leader_model_mask`；
- `leader_torque_off_mask`；
- `leader_calibration_crc32`；
- `leader_read_errors`；
- `leader_torque_errors`；
- `leader_rssi_dbm`；
- `leader_recovery_count`。

从电脑接受主臂样本到收到从臂 applied sequence 确认的时间作为控制链确认延迟。由于 XIAO 和电脑没有共享时钟，首版不把 XIAO 时间戳与电脑单调时钟直接相减来宣称单向网络延迟；XIAO 时间戳仅用于检测采样周期、停顿和重启。

## 错误处理

- 主臂任一舵机缺失或型号错误：主臂进入 `BUS_FAULT`，电脑拒绝启动。
- 主臂扭矩关闭或回读失败：主臂进入 `BUS_FAULT`，不得发布有效动作。
- 校准 CRC 不匹配：电脑拒绝启动，要求恢复正确的主臂 EEPROM 或选择匹配的校准文件，不自动写校准。
- 消息长度、版本、掩码或数值非法：电脑丢弃消息并累计协议错误。
- 重复、乱序或旧启动会话样本：电脑丢弃，不刷新有效样本时间。
- 主臂样本超过 150 ms：停止发送从臂命令并记录中断。
- WiFi 或 agent 失联：XIAO 重新发现；电脑等待健康状态，不使用旧样本。
- 发现服务收到无效报文：忽略并记录低频诊断，不改变当前健康连接。
- 有线备用模式失败：按现有 Feetech 总线错误处理，不自动切换到无线。

## 测试策略

### 电脑端自动测试

- 发现报文编码、解析、版本和非法输入测试；
- 主臂 raw/status 固定长度和字段范围测试；
- 32 位会话与序列号回绕、重复和乱序测试；
- 校准 CRC 的固定测试向量；
- 原始位置归一化与现有 `FeetechMotorsBus` 等价测试；
- 状态、掩码、CRC 和 150 ms 超时闸门测试；
- 主臂恢复目标及 1 秒混合测试；
- 有线主臂适配器回归测试；
- 启动脚本参数和预检失败测试；
- CSV 主臂指标字段与分析器测试。

### 主臂固件原生测试

- `STARTING`、`WAITING_AGENT`、`READY`、`BUS_FAULT` 状态转换；
- 舵机、型号和扭矩关闭掩码组合；
- 三次连续读取失败进入故障；
- 十次连续完整读取后恢复；
- 采样序列号及 32 位回绕；
- 校准 CRC 固定测试向量；
- agent 发现报文解析、nonce/IP 变化和超时；
- 非 `READY` 状态不产生有效动作样本。

### 构建和烧录闸门

1. 先运行电脑端测试；
2. 再运行主臂和从臂固件原生测试；
3. 编译两个 ESP32-C3 固件，不烧录；
4. 所有测试与编译通过后，才允许烧录；
5. 首次烧录时主臂舵机电源断开，机械臂受支撑，空间清空。

### 分阶段实机测试

1. 主臂 XIAO 仅 USB 供电，确认启动和自动发现，且没有位置写入；
2. 接通主臂舵机电源，确认 6/6 在线、型号匹配、扭矩关闭和 CRC 匹配；
3. 手动逐关节移动主臂，确认六路原始位置和电脑归一化结果正确，此时从臂保持断电；
4. 两臂接通，确认首次握手无跳动，再逐关节验证方向与响应；
5. 断开主臂 WiFi，确认从臂保持；期间移动主臂，恢复后确认约 1 秒平滑追赶；
6. 改变手机热点分配给电脑的 IP，确认两个 XIAO 无需重新烧录即可重新发现；
7. 切换到 `--leader wired`，确认现有 USB 备用模式没有回归；
8. 连续运行 10 分钟，保存主臂、从臂、网络和延迟 CSV。

每个实机步骤必须记录固件 commit、设备 USB/MAC 身份、供电安排、操作员观察和精确日志路径。没有真实观察和保存证据时不得标记通过。

## 验收标准

- 正常模式下主臂与电脑之间不需要 USB 数据线；
- 主臂六个舵机持续以 50 Hz 采样，实测平均频率在 45–55 Hz，正常掩码均为 `0x3f`；
- 主臂舵机扭矩在发布有效动作前全部确认关闭；
- 电脑归一化结果与现有有线 `SO101Leader` 一致；
- 主臂样本被电脑接受到从臂应用确认的延迟，在正常热点条件下 p95 小于 100 ms；
- 连续网络正常时没有意外超时、非法命令、旧会话接受或总线故障；
- 主臂断线时从臂保持，恢复后约 1 秒平滑追到正确姿态，无可见跳动或旧目标重放；
- 手机热点改变电脑 IP 后无需重新烧录任一 XIAO；
- `--leader wired` 能继续运行现有有线主臂；
- 10 分钟运行证据包含零意外拒绝、两个设备的健康状态和操作员安全观察。
